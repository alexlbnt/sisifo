# Ruínas — Plano de Implementação

> **Para agentes:** SUB-SKILL OBRIGATÓRIA: use superpowers:subagent-driven-development (recomendado) ou superpowers:executing-plans para executar este plano tarefa a tarefa. Os passos usam caixas (`- [ ]`) para acompanhamento.

**Objetivo:** dar ao Sísifo o cenário de ruínas gregas em pontilhado: a encosta entre ruínas na tela Hoje, colunas apagadas ao fundo das outras telas, login no estilo da referência, Modo Painel com a mesma linguagem e o logo novo ("pedra na encosta", sem quadrado), com ícones e splash gerados de novo.

**Arquitetura:** um motor puro de *dithering* (grade de luminância → pontos pela matriz Bayer 4×4) desenha colunas, tambores e encostas e tem testes. Por cima dele há duas saídas: um componente `<Ruins>` em `<canvas>`, que desenha uma vez e redesenha só ao mudar tema ou tamanho, e uma função que gera um `path` SVG para o templo dentro do `Hill`. As cenas (fundo, cume e login) são composições fixas com semente determinística.

**Stack:** React 19 + TypeScript, Tailwind v4 (tokens em `src/index.css`), Vitest (ambiente `node`), `sharp` (já instalado como dependência do `@vite-pwa/assets-generator`) para os ícones.

**Spec:** `docs/superpowers/specs/2026-10-30-ruinas-design.md` (mockups em `docs/superpowers/specs/2026-10-30-ruinas/`)

## Restrições globais

- Só visual: nenhuma store, `version`, schema, contrato de sincronização ou rota de API muda.
- As ruínas ficam paradas. A pedra continua sendo o único elemento animado. Sem `requestAnimationFrame` contínuo nem timers para o cenário.
- O cenário é decorativo: `aria-hidden`. O progresso da pedra mantém `role="img"` + `aria-label` com a porcentagem.
- A cor de destaque não muda: `--accent` `#2e4a9e` (claro) / `#93a6ef` (escuro).
- Fundo: escuro `--bg: #0d0f0e`; claro `--bg: #ebe7df`.
- A tipografia não muda (Bricolage Grotesque + IBM Plex Sans).
- Funciona offline: nada de imagem remota. O cenário é gerado no aparelho.
- Comentários e textos em português, na densidade do código atual.
- **Nenhum commit, push ou release sem ordem do Alexandre.** Os passos "Commit" abaixo só rodam depois da autorização dele; até lá, as mudanças ficam no diretório de trabalho. Versão sugerida no fim: `sisifo-v-1.12.0`.

## Foco de revisão

1. **Contraste em Finanças:** valores e listas sobre as colunas apagadas precisam continuar legíveis nos dois temas. As colunas do fundo nunca passam de `BACKDROP_DEPTH = 0.35` de luminância. Teste na Tarefa 2.
2. **Troca de tema com o app aberto** (Configurações e o modo automático do Painel): o canvas precisa redesenhar com a cor nova sem recarregar. Verificação manual na Tarefa 3.
3. **Tela muito estreita ou muito larga** (iPhone SE 320 px, monitor de 1920 px): a cena não pode estourar a memória nem sumir. A grade é limitada a `MAX_CELLS = 250_000`. Teste na Tarefa 1.
4. **`done = total = 0` e `done > total`:** a pedra fica no pé e no topo, sem `NaN`. Teste na Tarefa 5.
5. **Rotação do Painel e redimensionamento da janela:** redesenho com *debounce*, sem acumular *listeners*. O `ResizeObserver` é desconectado no `cleanup`. Verificação manual na Tarefa 6.

```ts
export interface Grid { cols: number; rows: number; lum: Float32Array }
export const MAX_CELLS = 250_000;
export function createGrid(cols: number, rows: number): Grid;          // limita cols*rows a MAX_CELLS reduzindo ambos na mesma proporção
export function plot(g: Grid, x: number, y: number, v: number): void; // arredonda x/y; ignora fora da grade; guarda o maior valor
export interface ColumnSpec { x: number; base: number; height: number; width: number; broken?: number; decay?: number; depth?: number; seed: number }
export function drawColumn(g: Grid, c: ColumnSpec): void;
export interface DrumSpec { x: number; y: number; length: number; radius: number; depth?: number; seed: number }
export function drawDrum(g: Grid, d: DrumSpec): void;
export interface SlopeSpec { from: { x: number; y: number }; to: { x: number; y: number }; thickness: number; depth?: number; seed: number }
export function drawSlope(g: Grid, s: SlopeSpec): void;
export function forEachDot(g: Grid, cb: (x: number, y: number) => void, mask?: (x: number, y: number) => number): void;
export function toDotPath(g: Grid, cell: number, dot: number, ox?: number, oy?: number): string; // "M{x} {y}h{dot}v{dot}h-{dot}z" por ponto
```

Algoritmo de referência: funções `column`, `drum` e `render` de `docs/superpowers/specs/2026-10-30-ruinas/mockup-direcoes.html`. Valores que ficam fixos:

- Topo quebrado: serrilha de −1 a +5 células por coluna de pixels.
- `decay` padrão `0.07` (ponto apagado para 20%).
- Arredonde `x`, `base`, `height` e `width` antes dos laços (o bug do mockup: índice fracionário não grava no `Float32Array`).

Composições (proporcionais a `cols`/`rows`, para valer de 320 a 1920 px):
- `backdrop`: 2 colunas grandes, de altura 0.75 a 0.9 de `rows`, uma inteira e uma quebrada (`broken: 0.3`), ancoradas no rodapé, uma perto de cada borda, mais um tambor caído. Tudo com `depth ≤ BACKDROP_DEPTH`.

- `login`: 3 colunas altas (0.7 a 0.95 de `rows`) espaçadas na largura, a do meio mais baixa e com o capitel destacado, como na referência; `depth: 1`, mais entulho no chão.
