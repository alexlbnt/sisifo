# Sísifo Desktop v1: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a Windows executable (Tauri 2) that loads the published Sísifo, lives in the tray, opens a global quick-capture bar with `Ctrl+Alt+Espaço`, starts with Windows, alternates the main window with the panel, and updates itself from GitHub Releases.

**Architecture:** A thin Rust shell in `desktop/` opens windows on `https://sisifo-two.vercel.app`. The main window, hidden in the tray, loads the full app and is the only owner of stores and sync. The capture bar is a light window (`desktop.html`) that never loads stores. It talks to the main window through a small message bridge over Tauri events: it sends commands and receives replies and summaries.

**Tech Stack:** Tauri 2 (Rust, WebView2) with the plugins `global-shortcut`, `autostart`, `single-instance`, `store`, `updater`, `process` and `log`; `@tauri-apps/api` v2 (dynamic import only); React 19 + TypeScript + Vite; Vitest.

**Spec:** `docs/superpowers/specs/2026-11-24-desktop-design.md`

**Scope:** this plan covers only the spec's **v1**. The synced Pomodoro, v2, v3 and the extras get one plan each, in that order. The tray item "Iniciar ou pausar Pomodoro" moves to the Pomodoro plan: in v1 the main window does not run the timer yet.

## Global Constraints

- The only remote origin allowed to call native commands is `https://sisifo-two.vercel.app`. In dev, `http://localhost:5173` is also allowed, and only in dev.
- Do not add any file to `api/` (11 of 12 used on the Vercel Hobby plan).
- Desktop versions use tag `sisifo-desktop-v-X.Y.Z`, with the number in `desktop/tauri.conf.json` and `desktop/Cargo.toml`. Site tags `sisifo-v-X.Y.Z` never build the executable. The first version is `0.1.0`.
- Only the main window loads stores (`loadLocalData`) and sync. `desktop.html` must never import `@/app/boot`, any `use*Store` from finance, personal or agenda, or `@/features/sync/engine`.
- Closing the main window hides it. Only "Sair" in the tray quits.
- The main window has `backgroundThrottling` disabled. Light windows keep the default.
- Default capture shortcut: `Ctrl+Alt+Space`. User-chosen shortcuts must not be AltGr combinations on ABNT2 (see Task 7).
- `@tauri-apps/api` is loaded only through `import()` inside `src/features/desktop/`, so the site bundle for browsers stays the same size.
- NSIS installer, per-user (no admin).
- UI copy in Portuguese, in the tone of the existing app. Commits use conventional commits in Portuguese and end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Shortcut pressed before the main window finishes loading** (cold start from autostart): the bar opens, shows "Sísifo ainda está abrindo…" and keeps the text typed so far. When the bridge answers, it works with nothing lost. Owner: Task 5 (client timeout test in Task 2).
2. **Main window on the login screen** (session expired): capture still saves locally, because the stores are local-first, and syncs after login. The host is installed whatever the auth phase. Owner: Task 4.
3. **Shortcut taken by another program:** registration fails without breaking the app. The Desktop card shows "Esse atalho já está em uso por outro programa" and keeps the previous one. Owner: Task 7.
4. **Enter with empty text or text that doesn't parse:** nothing is saved and the bar stays open with the text. Owner: Task 4 (host test) and Task 5.
5. **Main window open overnight:** the tray count changes at midnight without any interaction. Owner: Task 4 (day-rollover test).

### Task 2: Message bridge

**Files:**
- Create: `src/features/desktop/env.ts`, `src/features/desktop/bridge.ts`, `src/features/desktop/bridge.test.ts`, `src/features/desktop/tauriTransport.ts`
- Modify: `package.json` (dependency `@tauri-apps/api@^2`)

**Interfaces:**
- Produces:
```ts
// env.ts
export function isDesktop(): boolean; // '__TAURI_INTERNALS__' in window

// bridge.ts
import type { CaptureGuess } from '@/shared/capture';
export interface Transport {
  send(channel: string, payload: unknown): Promise<void>;
  on(channel: string, handler: (payload: unknown) => void): () => void;
}
export type BridgeCommand =
  | { type: 'capture.preview'; text: string; force?: CaptureGuess['kind'] }
  | { type: 'capture.submit'; text: string; force?: CaptureGuess['kind'] };
export interface BridgeReplies {
  'capture.preview': CaptureGuess | null;
  'capture.submit': { ok: boolean; message: string };
}
export interface BridgeSummary { pending: number; day: string }
export const CHANNEL = { command: 'sisifo:command', reply: 'sisifo:reply', summary: 'sisifo:summary', summaryRequest: 'sisifo:summary-request' } as const;
export class BridgeTimeout extends Error {}
export function createBridgeHost(t: Transport, h: {
  handle: <C extends BridgeCommand>(cmd: C) => Promise<BridgeReplies[C['type']]> | BridgeReplies[C['type']];
  summary: () => BridgeSummary;
}): { publish(): void; dispose(): void };
export function createBridgeClient(t: Transport, opts?: { timeoutMs?: number }): {
  request<C extends BridgeCommand>(cmd: C): Promise<BridgeReplies[C['type']]>; // rejects BridgeTimeout
  onSummary(cb: (s: BridgeSummary) => void): () => void; // also sends summaryRequest
  dispose(): void;
};

// tauriTransport.ts
export async function tauriTransport(): Promise<Transport>; // emit/listen from @tauri-apps/api/event, via import()
```
Wire format: a command travels as `{ id: string, cmd: BridgeCommand }` and its reply as `{ id, ok: true, value } | { id, ok: false, error: string }`. The default `timeoutMs` is `3000`.

- [ ] **Step 1: Write the failing tests** in `bridge.test.ts`, with an in-memory `Transport` (a `Map<channel, Set<handler>>` that delivers asynchronously with `queueMicrotask`):
  - `request returns the host reply`: host `handle` returns `{ ok: true, message: 'x' }` for `capture.submit`; `await client.request({ type: 'capture.submit', text: 'café 8,50' })` equals it.
  - `two concurrent requests get their own replies`: preview `'a'` and `'b'` resolve to values derived from their own text.
  - `request rejects with BridgeTimeout when no host answers`: no host, `timeoutMs: 50`, so it rejects `BridgeTimeout`.
  - `host errors become rejections`: `handle` throws `new Error('falhou')`, so the client rejects with message `'falhou'`.
  - `onSummary receives the current summary on subscribe and every publish()`: the callback gets `{ pending: 2, day: '2026-11-24' }` once on subscribe, then again after `publish()`.
- [ ] **Step 2: Run them and confirm they fail.** `npx vitest run src/features/desktop/bridge.test.ts`. Expected: FAIL (module not found).
- [ ] **Step 3: Implement `bridge.ts`, `env.ts` and `tauriTransport.ts`** with the signatures above. Request ids come from `newId()` in `@/lib/id` (or `crypto.randomUUID()`).
- [ ] **Step 4: Run the tests and confirm they pass.** Same command. Expected: PASS.
- [ ] **Step 5: Commit.** `git commit -m "feat(desktop): ponte de mensagens entre as janelas"`.
